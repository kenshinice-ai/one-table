# 交付记录：V1 基线 → V2 上线

## 体验（唯一硬指标）

| 体验 | V1 | V2 |
| --- | --- | --- |
| 打开即见完整一桌菜 | 是（数据内联在文档，代价见下） | **是**（默认菜单构建期算好写进 HTML） |
| 点开菜谱即见步骤 | 是 | **是**（详情负载随目录一起预取） |
| 改条件 / 换一组 / 换这道 | 立即 | 立即（新增单课程替换） |
| 打印 / 购物清单 / 存为图片 | 无 | 立即，全本地，无服务端 |
| 离线可用 | 否 | **是**（PWA，可安装） |
| 分享链接复现同一桌菜 | 否 | 是 |

## 传输量（记录用途，非约束）

| 项目 | V1（200 道） | V2 中途（400 道，未拆分） | V2 上线 |
| --- | --- | --- | --- |
| 首屏 HTML（gzip） | 86 KB | 170 KB | **9 KB** |
| 首屏 JS（gzip） | 230 KB | 261 KB | **198 KB** |
| 目录数据 | 内联在上面两项中 | 内联 | 91 KB（并行预加载，永久缓存） |
| 详情文本 | 内联 | 内联 | 50 KB（并行预取，永久缓存） |
| 列表缩略图（单张） | 268 KB | 268 KB | **12 KB**（320 档） |

拆分的动因不是省流量，而是 400 道菜整份内联会把文档撑到 170 KB gzip 并延迟一切；拆开后反而能做到「打开即有菜单」+「点开即有步骤」两者兼得。

**明确不设 KB 上限。** 任何以压缩体积为由删减读者可见内容的改动都不接受。
