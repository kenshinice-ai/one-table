# One Table V3 界面精修计划

> 2026-08-17 规划轮。原则不变：**完美体验第一**，始终亮色，不引入 UI 框架/图标库等新依赖。
> 设计权威沿用 `design-system/menu-planning-companion/MASTER.md`（61.8/38.2 黄金分割、8px 节奏、双像素描边 SVG 图标、150–240ms 动效、禁 emoji）。ui-ux-pro-max 自动推荐中与 MASTER 冲突的部分（如 Playfair Display SC）一律以 MASTER 为准。
> 前置事实：Luna-max 正在生图（200 张），R6 依赖其完成；R1–R5 均不依赖。

## R1 · 整体布局与黄金分割精修

**现状问题（对照线上截图）**

- 餐桌设置行 7 个下拉挤在一行，「菜单结构」摘要文本过长时折行 2–3 行，把整行撑到不等高（19 人 8 道菜时最明显）。
- 条件筛选 11 个下拉是无分组的平铺网格，扫读时没有层次。
- 主要区块间距不成节奏：设置行、筛选面板、菜单面板的上下留白各自为政。

**方案**

- [ ] **菜单结构摘要收敛**：触发器只显示「8 道 · 自定义」或「主菜 ×2 +5」这类单行摘要（`text-overflow: ellipsis` 兜底），完整结构进下拉后再展开。所有设置下拉锁定同一高度（56px），行内不再因文本长度参差。
- [ ] **筛选面板分组**：11 个控件分三个小节，节标题用现有 eyebrow 样式：
  - 「风味」：菜系与地区 / 烹饪方式 / 最高辣度
  - 「食材与饮食」：希望包含 / 不希望出现 / 饮食偏好 / 排除过敏原 / 健康指数
  - 「现场条件」：可用设备 / 单道最长时间 / 儿童友好
- [ ] **黄金比例落到三处**（不是到处硬套）：
  1. 主栅格维持 0.618 : 1（已有，确认响应式断点下不破坏）；
  2. 菜卡内图文比调到 38.2 : 61.8（现在约 92px : 剩余，接近但图偏小，改为容器百分比）；
  3. 详情弹层左右栏由 0.8 : 1.2 调为 0.618 : 1（38.2/61.8），图更大更沉浸。
- [ ] **纵向节奏统一**：区块间距走 8px 阶梯（16/24/40），设置行与筛选/菜单区之间统一 24px；面板内部 padding 统一 20px。
- [ ] **类型层级微调**：正文 15px 不动；`本桌菜单`/`条件筛选` 标题统一 24px（≈15×1.618）；汇总数字 39px（≈24×1.618）；全部用 token 落在 CSS 变量，不散写。
- [ ] 悬停态补齐：所有可点卡片 `cursor: pointer` + 150–240ms 过渡（部分按钮已有，逐一核对）。

**验收**：375 / 768 / 1024 / 1440 四档走查无折行破版、无横向滚动；设置行任何配置下保持单行等高。

## R2 · 图标系统（餐桌设置 + 条件筛选）

**决策**：不引入 Phosphor/Lucide 等依赖（触碰红线，且需求只有 ~17 枚）。在现有 `icons.tsx` 基础上手绘扩展——20px 网格、2px 描边、圆角端点、`currentColor`，与既有 Chevron/FilterIcon/TableMark 同一笔触。

**图标清单**

| -------------- | ----------------------------- |

| 上菜方式       | 揭盖餐罩                      |
| 总预算         | 圆形硬币（$）                 |
| 人均热量       | 小火苗                        |

| 菜系与地区     | 碗 + 筷                       |
| 烹饪方式       | 锅上火苗                      |
| 健康指数       | 单叶（复用 LeafScore 的叶形） |
| 希望包含食材   | 提篮 + 加号                   |
| 不希望出现食材 | 提篮 + 斜杠                   |
| 饮食偏好       | 叶片圆环                      |
| 排除过敏原     | 盾牌 + 对勾                   |

**实现方式**

- [ ] 移动端（<768px）图标保留、文字标签不省略（MASTER：禁止 icon-only 无标签）。
- [ ] 全部图标过一遍 4.5:1 对比度与 `aria-hidden`（装饰性，语义仍在文字标签上）。

**验收**：17 枚图标风格并排看是同一套笔触；选中态颜色变化在中/EN 两态都正确。

## R3 · 本桌菜单滚动（长菜单不再撑爆页面）

**现状问题**：19 人 8 道菜时菜单列表极长，汇总数字和「换一组」被推到几屏之外；筛选面板早已到底，右栏还在继续。

**方案：菜单面板变成自滚动容器，关键信息常驻**

- [ ] 桌面（≥900px）：`.menu-panel` `position: sticky; top: 16px; max-height: calc(100dvh - 32px)`，内部三段式——标题区固定、菜品列表 `overflow-y: auto`（细滚动条样式化）、**汇总 + 换一组 + 四个动作按钮固定在面板底部**。任何长度的菜单，总价/热量/操作都一眼可见。
- [ ] 课程节标题在列表内部 `position: sticky; top: 0`，滚动时当前课程名保持可见（既有分组结构直接受益）。
- [ ] 列表顶/底加渐隐遮罩（8px 线性渐变）提示可滚动，避免「看起来到底了其实没有」。
- [ ] 移动端不做内部滚动（双层滚动是手感灾难）：改为**吸底汇总条**——总价 + 人均热量 + 换一组按钮 `position: sticky; bottom: 0`，安全区适配（MASTER 已有约定）。
- [ ] `prefers-reduced-motion` 下滚动行为不变（无平滑滚动强制）。

**验收**：8 道菜 + 19 人配置下，桌面端汇总与操作不出视口；移动端拇指区常驻换一组；无双层滚动冲突（内部滚到底后正确交还页面滚动）。

## R4 · 详情页打开体验（图片与食材「等一下」的根因与修法）

**诊断**（为什么感觉不如之前顺畅）

1. 弹层里的主图请求的是 **640 档**，而列表已经加载过的是 **320 档**——打开弹层时浏览器要重新发起一张没缓存的图，冷缓存时灰底可见约 0.3–1s。
2. **食材缩略图（每道 4–6 张 64px 图）在弹层打开那一刻才开始请求**，逐张弹入。
3. 数据本身不慢（详情文本已随目录预取，本地就有）；慢的全是图。

**方案：让图在用户点开之前就已在路上**

- [ ] **320 → 640 无缝升档**：弹层主图先立即渲染已缓存的 320 档（模糊放大 + `filter: blur(0)` 过渡），640 档 `onload` 后淡入替换。打开瞬间永远有图，清晰度 0.2s 内跟上。灰底彻底消失。
- [ ] **悬停/按下即预热**：菜卡 `pointerenter` / `touchstart` 时用 `<link rel=prefetch>` 或 `new Image()` 预取该菜的 640 主图 + 全部食材缩略图。鼠标从悬停到点击的 200–400ms 足够 5G 拉完这几十 KB。
- [ ] **当前菜单空闲预热**：目录到达后 `requestIdleCallback` 把**当前一桌菜**（最多 10 道）的 640 主图与食材图静默拉入 SW 缓存——本桌菜单里的任何一道，点开即满清晰度。只预热当前菜单，不预热 400 道。
- [ ] 食材缩略图容器给固定尺寸 + 底色占位（已有 28px 格子，确认无 CLS），图片 `decoding="async"`。
- [ ] 弹层入场动画定为 180ms 缩放淡入（现在是瞬开）：给图片到位一个自然的节拍，同时符合 MASTER 150–240ms 区间。
- [ ] Luna-max 新图到位后同样受益（占位图逻辑不变，有图走图）。

**验收**：热缓存下打开详情无任何可见加载过程；冷缓存下主图以 320 模糊版即时出现、640 在 0.5s 内淡入；食材图不逐张弹跳。

## R5 · 「保存食谱（照片）」分析与方案

**结论：合理，建议做。** 理由：

- 场景真实——单道菜发家庭群/收藏，比整桌菜单卡更高频；「今晚就做这道」是最小分享单元。
- 基础设施现成——`share-card.ts` 的 canvas 渲染、字体、品牌版式、blob 下载全部复用，增量只是一个新版式函数。
- 与打印互补——打印是整桌的「作战文档」，单菜卡是社交的「种草图」。

**版式方案（3:4 竖版 1080×1440，微信原图友好）**

- 上 38.2%：菜品照片（无图的菜用品牌色几何占位版式，不出 Coming Soon 灰盘——分享图里的占位要像设计，不像缺失）
- 中：菜名（衬线大字）+ 课程/时长/热量/健康叶
- 下：食材清单（按当前人数换算，最多 8 行，溢出「等 N 种食材」）+ 简版步骤（最多 4 步、每步一行截断）
- 底：品牌 wordmark + 「一桌 · 为一桌人配一桌好菜」+ 分享链接短文案

**实现清单**

- [ ] `share-card.ts` 新增 `renderRecipeCard(recipe, detail, guests, locale)`；无图菜走几何占位分支。
- [ ] 详情弹层动作区加「保存食谱」按钮（ImageIcon 复用），生成中态复用 `saving` 文案。
- [ ] iOS Safari 注意：blob 下载落到「文件」而非相册，按钮旁加一行小字提示长按图片可存相册（或改为新开标签展示图片由用户长按——实现时二选一，以真机手感为准）。
- [ ] 单测：食材超 8 行截断、无图分支、中英两版式。

**暂不做**：分享到社交平台的 Web Share API 集成（iOS/安卓行为差异大，先观察保存按钮使用率）。
